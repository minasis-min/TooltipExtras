# Build dependencies

Use Windows x64, PowerShell 7 and .NET SDK 10.0.302 (latest patch in that feature band is allowed). The API target is Dalamud 15. The build references are Dalamud 15.0.3.6-117-gb17c64aca-estell.48. Runtime support is determined by feature-specific contracts, not DLL version or module ID. API number alone does not establish compatibility.

Host references are Dalamud, Dalamud.Bindings.ImGui, FFXIVClientStructs, InteropGenerator.Runtime, Lumina, Lumina.Excel and Newtonsoft.Json. The checks additionally reference host-provided Serilog for real SeString parsing and Microsoft.Extensions.ObjectPool for the host Lumina color builder. Neither is a plugin runtime dependency added by TE. Obtain the matching files from a local Dalamud SDK installation. They are not redistributed. Exact reference file versions and SHA256 hashes are recorded in `reference-lock.json`.

Reference module IDs (build provenance only; not runtime allowlists):

- Dalamud: `0982f2f8-b2dd-42d5-ad75-acd63588fc42`
- FFXIVClientStructs: `f2ce2d31-ef6f-45f8-a331-8b2785f00c81`
- Price Insight 2.11.5.0: `6ba90fe2-e666-4a94-b47d-abf7a855391e`
- Item Vendor Location 2.14.0.1: `ac0d5828-354a-4313-93fe-76680dcbb3fb`
- Simple Tweaks 1.15.0.7 (only the specific verified price layout exception): `f4d37b94-0e44-44cd-83fa-751e1fded533`

Glamour Log uses `GlamourLog.IsItemInArmoire`, `GlamourLog.IsItemInDresser` and `GlamourLog.IsSetComplete` with uint inputs and bool results. The adapter checks registration and invocation results instead of a fixed Glamour Log version.

MinasisUI 0.1.14 is embedded from the four pinned source files in `vendor/MinasisUI`; hashes are checked before building. No independent UI DLL is required. Historical WhichPatch data is pinned to upstream commit `5578bad66709f92811fe43b5c533144593a45d70`, rather than retrieved from the network at runtime. A future data update requires a reviewed plugin update.

Paths below are relative to the repository root; run the commands from that directory.

```powershell
pwsh -NoProfile -File ./scripts/Prepare-References.ps1 -DalamudDirectory '<your matching Dalamud SDK directory>'
pwsh -NoProfile -File ./scripts/Build.ps1
```

The first command copies the seven plugin reference DLLs and the test-only Serilog and Microsoft.Extensions.ObjectPool DLLs into the ignored `.dependencies/Dalamud-15.0.3.6-estell.48/` folder. The second verifies pinned sources/references, builds, runs checks and updates the Dev bundle without creating a ZIP or package staging directory. Add `-Package` explicitly when preparing distribution files: `pwsh -NoProfile -File ./scripts/Build.ps1 -Package` creates `artifacts/distribution/<Version>/TooltipExtras.zip` and `icon.png`. Packaging staging is removed in finally after success or failure. Caches, temporary files and build output remain under the checkout's ignored `.work/` and `artifacts/` folders. The checkout itself can be on any writable drive.

The ZIP contains runtime files and required license notices only. It is not tracked by Git. No logs, user settings, host DLLs, cooperative fork, old icons, debug PDBs or research material are included. `PathMap` removes the local build root from generated debug metadata. SourceLink generation is disabled to avoid absolute development paths in its debug document map.

Licenses and attribution: [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

The build also writes a complete Dev bundle to a fixed ignored artifacts/plugin/ directory. Use -DevOutputDirectory to select an existing Dev folder. The plugin DLL, manifest, deps.json, icon and required licenses are copied together; saved settings are not overwritten. The manifest uses ApplicableVersion=any; native access remains gated by the feature contracts.

## Runtime compatibility contracts

`src/TooltipExtras/CompatibilityContracts.json` is embedded in the DLL. It records only the used API signatures, enum values, native field positions/types and audited operations. IL tokens, including native call signatures, are resolved to names; assembly versions and module IDs are excluded. Same-assembly called methods are included for the audited operations. Per-target node ownership, geometry and restoration checks remain in effect.

`tools/CompatibilityProbe` verifies contracts against explicitly supplied SDK/provider directories. Use `dotnet run --project tools/CompatibilityProbe -- check <contract-file> <SDK-directory> <provider-directories...>` after sourcing `scripts/Environment.ps1`. Its `generate` mode is for reviewing a new baseline, never for silently accepting an incompatible update. Host contracts are checked once per load; provider contracts are checked when active plugins change. Status changes are written to Dalamud Debug logs. Native array diagnostics have a separate guard.

An API-level load rejection happens before plugin initialization and is reported by Dalamud. Even matching managed contracts cannot prove every game update compatible; an unexpected live node shape is rejected and the native display is retained.

## Tooltip callback relay

### Exclusive text output

`ExclusiveOutput` defaults to true and preserves a saved false value. The legacy adapters below remain available when it is false. This mode is limited to reviewed producer entry points; connection failure, unsupported native-node producers, plugin unload and TE disable do not establish a universal vanilla-output guarantee.

DR invokes reviewed formatters against private modification lists and restores the incoming list reference in a finally block. Generated operations never enter the manager's real application list, including on parse/source failure. Append instructions and recognized replacement contributions go to the current-target panel. The non-gear replacement's cached native prefix is discarded rather than restored. Unsupported formatter registrations are withheld while this connection is owned. Other registration owners and explicit unregistration remain respected.

AT, the Simple text adapter and Item Vendor Location use a shared `StringArrayData.SetValue` hook. Its C++ boolean parameters are explicitly marshalled as one byte. The fast path forwards unrelated arrays/threads unchanged. Only during a reviewed synchronous formatter call, a temporary string-array header and pointer table receive intercepted writes; pinned temporary values support subsequent formatter reads. Actual native arrays, subscribers and allocation tables are not modified. Temporary pins and pointers are invalidated at scope exit, including failure. Hook disposal requested during a scope completes after that scope. No borrowed pointer or text is exposed through the status IPC.

AT checks the five original formatter bodies and seven additional per-type contracts (coffer, curated list, market price, unlock, glamour-ready set, ingredient patch and location). Each additional callback needs its own matching contract; unreviewed callbacks remain withheld. An originally null target slot is treated as an empty baseline only in the private capture view. Simple uses its existing per-formatter operation contracts and a private number-array view for materia counts. Item Vendor Location uses a temporary managed tooltip view with audited constructor/indexer bodies. Its successive reads see its own staged writes. These views are not passed to native array allocation or normal native tooltip layout routines.

Before using a temporary view, TE checks the reviewed Dalamud hook-manager operations and holds its registration lock through the synchronous formatter. A second registered hook at the setter address, a missing/disabled TE hook or a redirected entry point blocks formatting. Hook connection failure after an adapter's managed registration boundary was validated keeps that boundary active and withholds its output. This guard covers the inspected Dalamud hook backends, not arbitrary external native patching. Hook-registry scans and formatter capture costs have not been measured in-game.

Simple AdditionalItemInfo instead calls the provider's existing `GetInfoLines(uint)` API, with an operation contract covering its actual formatter. Its native AfterItemDetailUpdate node builder is skipped. Source settings and collectors remain owned by the source plugin. Simple's name-node generator is skipped in exclusive mode: current ItemName/GlamourName array data is combined with the existing GlamourNameText helper, using the current native name color. No source replacement node is allocated or updated; a verified previously created source node may be hidden during mode migration. Current-target data is invalidated on item changes. ShowItemID and ItemHotkeys are intercepted in fields2 and64 through the shared text sink, preserving the provider's formatting and actual hotkey operations. An inherited OnGenerateItemTooltip with exactly one ret instruction is left alone; API/image-only producers are not incorrectly classified as failed text producers. Price Insight and the other native-node/image adapters still use their existing separation paths. The extras-panel error path is independent of active separation in exclusive mode; a draw submission does not prove external capture exclusion. Local failure notices are deduplicated per category per plugin load.

The Allagan Tools adapter reuses the loaded InventoryTools instance and its existing CriticalCommonLib TooltipService. It relays AmountOwnedTooltip, SourceInformationTooltip and UseInformationTooltip registrations through forwarding subclasses, using the original enabled getters and original callbacks. HeaderTextTooltip and FooterTextTooltip are also observed when both registrations are available. Two owned boundary callbacks bracket this dispatch without changing the original callbacks' relative order. Before native layout generation, the shared text transaction removes only the exact observed header/spacing additions when the final Description, Effects and Levels fields contain no other native contribution. An untransferred contribution in these fields, failed relay, changed dispatch ownership or disabled TE keeps native decoration. No text-label matching or AT setting changes are used. It neither collects inventory data nor formats sources/uses independently. Provider assemblies and source code are not bundled.

AllaganNative checks the used string-array layout and SetValue operations both against TE's host types and against the actual callback pointer types' assembly. AllaganProvider checks the dispatch-loop body, string-accessor bodies and callback signatures. Callback body hashes are deliberately not pinned: the original formatter runs as supplied, then byte-prefix validation accepts only a single appended field among Description, Effects and Levels. Structural changes or a changed dispatch loop stop this adapter. Successful earlier sections remain on the panel if a later section is rejected.

The relay uses Dalamud's internal exposed-plugin wrapper and the provider's hosted service container; these are not stable public IPC. Connection failures leave native callbacks unchanged. Only the proxy entries still owned by TE are restored on detach. A native write failure stops further relay writes and attempts to restore the provider result. This fallback does not guarantee recovery from arbitrary native memory corruption.

The Simple Tweaks extras adapter relays only AdditionalItemInfo.AfterItemDetailUpdate through the existing EventSubscriber.Method slot. The source tweak object, settings, event enable flags and formatter remain intact. The original callback creates its own text node; TE copies its SeString and reverses only the verified window height, component surface height and footer displacement. A changed shape leaves the native result intact. No node is allocated or destroyed by TE. The original before/after operation contracts and event dispatch body must match, and the actual callback native ABI is checked. ID/action and desynthesis changes are outside this adapter. Source configuration must remain enabled. Holding Ctrl retains the last successful extras result for the same visible target if the source produces no visible node; target changes, hide and disabling invalidate it. Game-driven changes to the base tooltip itself are not suppressed.

Item IDs are captured from the generated ItemDetail category node only while the source Show ID feature is enabled and its operation/signature contracts match. A final color-3/ID-text/color-reset suffix with the exact audited decimal/hex format is extracted; unmatched text remains native. No item ID is independently obtained or calculated. Only node text is changed and restored, not the native category row's dimensions; multiline category reflow and recording-frame behavior need live verification. Action IDs and desynthesis are not included. The same Simple Tweaks checkbox controls these item IDs and dedicated extras, with separate compatibility checks/status.

AT captured text has only its outer newlines trimmed for its audited single-text-payload format. Colors, link metadata, internal line breaks and indentation remain. Owned/locations, sources and uses are joined with one line break; spacing between plugin sections is unchanged.
## Additional generated tooltip relay

The text relay supports FoodStats, MateriaStats, DesynthesisSkill, CollectableRewards, LogosTooltip, TrackFadedRolls, TrackGachaItems and TrackOutfits. It obtains the source's existing GenerateItemTooltip hook address through its loaded manager and installs a Dalamud hook with the same audited native signature. During that synchronous generation call only, selected SubTweaks registrations are temporarily replaced with forwarding subclasses. A finally scope restores the original instances, including on failure; source settings and Enabled values are not changed. The source callbacks run at their original position and only once per invocation. Native-hook ordering and live behavior still require game verification.

The callbacks' before/after string fields are copied. Completed effects/stat rows are retained for rewrites; append-only features must match an exact byte prefix. Before values and the materia stat-line count are restored before normal layout continues. Write/readback failures attempt to restore all original provider results and stop the adapter. Exceptions are contained so source error UI does not receive a synthetic proxy. A module-specific dispatcher/native contract and separate contracts for each formatter allow one incompatible formatter to fall back without disabling the others. Exact source instances identify their assemblies, including while older load contexts remain present.

UnlockablePreviews and PaintingPreview use the original post-update callback and resolved lastImage field. The original image selection (including character-dependent selection) is not reimplemented. TE loads that resolved image path through ITextureProvider for ImGui presentation. Only ISharedImmediateTexture is retained; frame-borrowed wraps/handles are used only in the current UI draw. No source texture/node is disposed or recreated by TE. The validated source image is hidden immediately after generation, without waiting for the ImGui texture. Native geometry is reversed at PreDraw once source-owned nodes, positions and component heights match. Heights observed inside GenerateItemTooltip are diagnostic only because native layout may still belong to the previous item. Collapse inverts the current generated image geometry, never an incoming window snapshot; current visible native text bounds prevent preview/price shrinking below body content. The preview-only bottom margin (16px for unlockable previews, 8px for paintings) is removed along with the image, while the measured native body padding is preserved. Hidden ancestors, empty text, control hints and foreign append nodes do not contribute; unsupported transforms defer shrinking. Requested updates restore geometry without showing the same-target source image. While layout is pending, AddonArgs.PreventOriginal skips only that native draw, with a monotonic 100ms deadline per target that repeated updates cannot extend; texture loading never delays the native text. A separate API compatibility check gates this optional draw suppression. No multi-item image cache is added. The painting-specific root-height synchronization exception accepts only a root becoming exactly equal to the captured window height, with every other value unchanged. Source native images remain allocated and owned by their original plugin while hidden.


Live load, native-hook chain ordering, image loading/DPI, food changes, modifier keys, reload/disable, performance and recording frames are not established by the offline model checks.

GlamItemNames uses a separate forwarded callback in the same temporary SubTweaks scope. The existing replacement text node must match the source's ItemName + NewLinePayload + GlamourName exactly before TE copies it. TE hides that source-owned replacement and shows native text node 33; it does not rewrite names, resize the header, query item sheets, or allocate/destroy native nodes. Disabling the relay restores the source visibility only while node identity and copied content still match. Its managed operation and the provider text-node ABI are checked separately.

Name colors are sampled from the original native title node and the provider replacement node at PreDraw, after the game applies current text colors. RGBA bytes are transported using Lumina color payloads, with resets around each name; TE does not derive rarity or query a color sheet. The exact native color field/layout and required builder signatures are checked. Unrelated overload additions do not invalidate a required API signature. Requested updates preserve captured name data; only explicit restore/disable/unload returns the provider replacement to view.

## Coordinated restoration

Price restoration uses the original verified append delta against its exactly tracked live layout, with node identity, content and all window heights still checked. Preview restoration reports an accepted geometry change to the price adapter, including restoration during source detachment. Turning off price separation restores the price's current native position and append height without revealing the preview; both preview restore endpoints follow that exact change. Visible native price updates are peeled only when their append geometry matches, and preview endpoints track the latest visible price delta without cumulative addition. Deferred price restoration retains its snapshot for a later safe retry. Lifecycle hide/finalize/target invalidation remain explicit ownership boundaries.

Preview capture stores immutable source-before/Generated geometry separately from mutable expanded/compact restore endpoints. Painting Root synchronization always uses source-before, including after initial collapse or price restoration. Native body measurement rejects an otherwise eligible visible text whose parent path terminates before the root; explicit hidden/foreign/control exclusions are still skipped. Tests exercise the same shared layout records and restore plans used by the adapters; native lifecycle execution and rendering still require live verification.

## Same-target requested updates

While separation remains enabled, RequestedUpdate for the same exact item key/addon keeps the existing price and preview hidden. It does not expand their geometry merely to let the native/source generators regenerate them. The native layout and compatible source callbacks run normally; changed output is captured again and verified before presentation. Target changes clear old price ownership, while explicit OFF/hide/unload still use coordinated restoration. No HQ/NQ content is synthesized or delayed, and no multi-item cache is introduced.

A shared geometry pass attempts separation at PostRequestedUpdate and before native Update resolves screen coordinates, then revalidates at PreDraw for later producers and asynchronous changes. All native access in the pass requires PriceNative compatibility. Unknown/incomplete layouts defer to later checked passes. Source color sampling and the optional 100ms draw-only suppression remain at PreDraw.

## Shop and market text relay

The Daily Routines adapters forward the existing OmenTools TooltipManager ItemDetail and ActionDetail listeners once. Reviewed item callbacks cover AutoShowItemNPCShopInfo, BetterMarketBoard, OptimizedSalvage and AutoDisplayIDInformation. The AutoPreviewColorsInDye callback is allowed to retain its original state-only behavior; its separate preview window is not a text addition. The reviewed action callback is AutoDisplayIDInformation. The adapters do not permanently replace module registrations, run collectors independently, query market services, or suppress the ShopInfo operation. Additional or duplicate callbacks, changed assemblies and failed contracts retain native text.

The item capture fields are UICategory (2), Description (13) and GearAbilityInfo (35), selected from actual registered producers. The action field is Category (1). Capture requires an observed change during the original callback, the same array/target/registrations and a verified boundary against the manager's original text. Dormant item groups are ignored. Exact append text is copied byte-for-byte; the audited salvage ability formatter additionally permits whitespace-only changes to the original prefix, comparing complete SeString tokens including formatting, glyphs and values. Only the added suffix is presented, and the exact original bytes are restored. Empty original item descriptions are supported: their dedicated visibility bit is cleared when removing the added description, without clearing the shared crafting/repair group. All selected text fields and flags use a single transfer plan with readback and best-effort rollback; forward and rollback buffers are prepared before mutation. An ambiguous field stays native while independently verified fields can still be separated.

A replacement host listener holds the original registration object intact in its owner's scoped list. It observes the original IsRequestedToClear flag before forwarding. TE detachment restores only its owned listener and never resurrects a registration already removed by the source. Attachment checks that the host listener invocation order is preserved. Internal host dispatch/unregistration operations and the provider operations have separate compatibility contracts; this is not a stable public IPC. Provider width adjustments remain owned by the source. No native hook, image cache or additional remote request is added. Live lifecycle ordering, layout, source reload, async prices and performance still require verification.

Restoring arrays alone is insufficient because Omen may already have materialized the additions during its own reflow. For selected item fields 2, 13 and 35, the item adapter now restores CategoryText, DescriptionText and MaterializeText as applicable, regardless of whether the baseline description is empty. Description and ability text are measured again, their containing groups follow the text-height delta while retaining existing padding/other rows, and UpdateGroupPositions updates placement. Only an empty baseline description hides its dedicated DescriptionGroup; the shared repair group retains its visibility and standard content. Category keeps its existing row geometry. Direct parent ownership, node types, text bounds and group-height bounds are required. Text/visibility are read back, and managed failure restores the actual pre-transfer node text, heights and visibility along with the arrays/flags. No tooltip generator or provider collector is rerun. The native fields and operations have a separate DailyLayoutNative contract.

For the reviewed salvage contributor in field 35, a rebuilt standard prefix can differ from the cached native text. A narrow fallback reads the actual provider's current localized label and colon through its existing getters, then requires a unique line boundary, the audited ColorType value (0, 32 or 45), a decimal with two fractional digits, the matching color reset and the optional plain-text bracketed note. It copies that generated suffix and restores the exact cached native baseline. It rejects an already contaminated baseline, duplicate labels and other payload/value shapes. The original observed-change, visible-group, target, registration and provider checks remain required. General field-35 prefix extraction also requires a new line boundary, preventing a partial numeric prefix from being mistaken for a complete standard row. The fallback does not evaluate item sheets, calculate skill values or generate localized content independently.

Presentation verification distinguishes raw input from native text flow. SetText and string-array restoration require exact byte readback. After ApplyTextFlow and positioning, the rendered text may contain native line wrapping: verification compares complete SeString tokens while ignoring whitespace/newline differences. All glyphs, values and formatting payloads must still match; retained NPC/skill information fails this check. This avoids treating normal word wrapping as a failed transfer and stopping the adapter. Failures now identify the field and distinguish raw text writeback, flowed content and visibility.

Native text flow reads OriginalTextPointer while writing NodeText. During the synchronous presentation transaction, input now uses a separate pinned, NUL-terminated buffer rather than aliasing that destination. WordWrap/MultiLine are temporarily enabled and Ellipsis is temporarily disabled so the restored standard content is not abbreviated during measurement. The original flags are restored in finally, OriginalTextPointer is rebound to node-owned storage if it still points to the temporary input, and every pin is released on success/failure. No temporary pointer survives the transaction. Content is checked independently after flow, measurement and positioning; failures identify the stage without recording item text.

DR item fields now use independent instances of the existing TextTransferPlan, following the existing Allagan section transfer pattern. Description (13), including completed market/NPC text, can remain transferred when another field's layout fails. Each field snapshots the current flags, so rolling back ability text cannot re-enable a description already removed. A failed field is skipped for the same target after its native array/flags/layout rollback has been verified; changing targets or reconnecting permits another attempt. An unverified rollback halts further writes. Already transferred sections remain in TE until source forwarding clears them before native additions can be generated again. No additional source callback or market query is run.

Item transfers are staged during the original callback and committed at PostRequestedUpdate, after native generation. One pending item/addon/string-array/number-array identity is retained; a newer request, hide, clear or disposal cancels it. Current registrations, array bytes and native node content must still match before committing. This prevents writing to the previous item's node or measuring unfinished geometry. Group resizing subtracts the measured generated text height rather than a stale node Height. Immediate SetText validation uses the same glyph/payload invariant as subsequent wrapping checks.

The reviewed NPC callback contributes an empty ShopInfo (63) operation. Omen can enable the ShopSellingPrice visibility bit even for an already-empty baseline, leaving a blank native row. After the source callback and native update, TE reconciles that row only while the reviewed NPC registration remains present, field 63 is empty, node ownership matches and the shop node has no visible content. The checked ShopSellingPrice bit and that group's visibility are cleared before repositioning. Nonempty array/visible-node prices remain native. The shared transfer plan handles flags/visibility rollback without rewriting shop text. Disabling the adapter returns to ordinary source updates.

Description additions from the reviewed NPC and market callbacks are copied from their completed current-target Append operation before Omen applies it. Only that one operation is removed from the callback's output list after validation and allocation; other operations, including empty ShopInfo, remain. This avoids reconstructing the native description from Omen's cached original text during rapid item changes. The actual formatter still runs once. Temporary forwarding delegates occupy only the synchronous source-call scope and are restored in reverse order in finally. Concurrent dictionary compare-and-update restores only owned proxy entries in the latest immutable list, preserving foreign additions and avoiding duplicate originals; a removed proxy is not resurrected. Retained proxy snapshots are inert outside their scope. Duplicate description operations, unexpected model shapes, failed selectors and mismatched targets leave the source output list intact.

Captured direct output is published once the original callback has finished and its source identity, current target/addon and registrations have been validated. Native presentation transfers still wait for PostRequestedUpdate with their array/content/layout guards. A later description change or rejected native transfer therefore cannot discard an already diverted direct addition. Target changes, new requests, hide, disable and disposal still clear owned text; direct output is never written back as a native cached description.

An immutable registration snapshot also caches callback classification, fields, NPC presence and forwarding observers. Identity is rechecked at source and native commit boundaries. Changes such as module enable/disable or instance replacement rebuild that metadata on the next requested update without replacing the TooltipManager lifecycle listener; obsolete observers are released. Unchanged lists avoid repeated callback enumeration and observer construction. Unchanged/dormant fields are compared before allocating native baseline/generated copies. Skill validation and non-gear template access are shared between direct and fallback paths. Flow comparisons stream Unicode scalar/payload tokens, preserving existing whitespace/payload rules without a byte array and string for each character. These allocation reductions do not establish game FPS improvements.

The reviewed non-gear salvage callback rebuilds Description (13) from the current item's description before contributing skill rows. Its actual localized macro structure, unique boundary, skill value/color/reset and current-target Contribute operation must match. If the generated native prefix matches this request's incoming description under the existing glyph/payload invariant, the skill addition is copied and the whole redundant description operation is omitted, preserving the native request input without a writeback. Otherwise the existing staged, verified native transfer remains available using the exact prefix from the observed source output. A cached baseline or a matching text label alone is insufficient evidence for rebuilt-prefix attribution. No item sheet, skill calculation or formatter is independently evaluated. Temporary pre-write array or presentation mismatches defer until the next normal requested update; unsupported structures remain blocked and an unverified rollback still stops writes. No polling or multi-item cache is added.
